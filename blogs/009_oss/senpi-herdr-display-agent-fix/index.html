senpi에 보낸 한 줄 수정: herdr 사이드바 표시 이름 버그

2026-10-29 noisonnoiton

Interactive Diagram

새 탭 ↗

진행 중인 기여

2026-10-29 12:07 KST에 GitHub CLI로 확인한 기준으로 OmO 이슈 #11397과 senpi PR #4582는 열려 있다. PR은 draft가 아니고 아직 머지되지 않았다. 아래는 배포 완료 회고가 아니라 원인 분석부터 패치와 검증, PR 제출까지의 기록이다. 리뷰나 머지 상태가 바뀌면 이 글도 갱신할 예정이다.

여러 에이전트의 저장소 협업을 정리하던 중 herdr 사이드바에서 이상한 점을 발견했다. 다른 pane에는 claude, hermes처럼 에이전트 이름이 보이는데, OmO pane에는 대화의 세션 이름이 나왔다. 세션 이름을 고치면 에이전트 라벨도 함께 바뀌었다.

수정할 실행 코드는 한 줄이었다. 하지만 그 한 줄을 PR로 내기까지는 제품과 엔진의 저장소 경계를 찾고, 잘못된 동작을 잡는 테스트를 만들고, 저장소의 변경 기록과 QA 규칙을 따라야 했다.

손으로 고친 표시 이름이 다시 바뀌었다

섹션 제목: “손으로 고친 표시 이름이 다시 바뀌었다”

처음에는 herdr의 pane report-metadata --display-agent로 표시 이름을 직접 바꿨다. 잠깐은 원하는 이름이 보였지만 다음 보고 때 덮어써졌다. 화면에서 값을 바꾸는 것만으로는 그 값을 계속 보내는 쪽을 이길 수 없었다.

문제가 있던 구성은 OmO Native이며 실제 엔진은 senpi다. herdr 프로토콜은 이 pane의 에이전트 종류를 pi로 보고한다. 여기서 pi라는 종류를 바꾸려는 것이 아니라, 사이드바에 표시하는 에이전트 라벨과 세션 제목을 분리하려는 것이다.

원인은 reportTitle의 두 필드였다

섹션 제목: “원인은 reportTitle의 두 필드였다”

보고를 보내는 코드는 packages/coding-agent/src/core/extensions/builtin/herdr/index.ts에 있었다. 내장 herdr 확장의 reportTitle은 세션 이름을 읽어 pane.report_metadata에 보냈다. 문제는 title뿐 아니라 display_agent에도 같은 이름을 넣었다는 점이다.

필드담아야 하는 값이 버그에서의 값
title세션 이름세션 이름
display_agent사이드바의 에이전트 라벨세션 이름
프로토콜의 agent에이전트 종류pi, 변경 대상 아님

herdr는 display_agent를 사이드바의 에이전트 라벨로 사용한다. 따라서 세션 이름 변경을 보고할 때마다 라벨까지 세션 이름으로 갱신됐다. 수동으로 지정한 표시 이름이 오래 가지 않던 이유도 같은 보고 경로에 있었다.

제품 이슈와 수정 PR의 저장소가 달랐다

섹션 제목: “제품 이슈와 수정 PR의 저장소가 달랐다”

사용하는 제품은 OmO이므로 먼저 code-yeongyu/oh-my-openagent#11397에 현상과 원인을 적었다. 하지만 문제 코드는 제품 저장소가 아니라 엔진인 code-yeongyu/senpi에 있었다.

그래서 senpi를 fork하고 fix/herdr-display-agent-label 브랜치에서 수정했다. PR도 senpi#4582로 열었고, 원래 이슈에는 수정 PR 링크를 댓글로 남겼다. PR 제목은 fix(herdr): keep the sidebar agent label on the branded command다.

이슈와 PR이 다른 저장소에 있으므로 PR이 머지돼도 원래 이슈가 자동으로 닫히지 않을 수 있다. 코드가 수용됐는지와 사용자에게 제보된 문제가 정리됐는지는 두 링크에서 각각 확인할 필요가 있다.

한 줄 수정으로 이름의 책임을 분리했다

섹션 제목: “한 줄 수정으로 이름의 책임을 분리했다”

새 설정을 만들지 않고 이미 있던 브랜드 명령 APP_COMMAND를 사용했다. OmO에서는 omo, 단독 senpi에서는 senpi인 값이다. 세션 이름은 title에만 남기고 display_agent에는 이 명령을 보낸다.

실행 코드 한 줄을 바꾸고 의도를 설명하는 주석 한 줄을 추가했다. 프로토콜의 에이전트 종류는 여전히 pi다. 사이드바 라벨을 고치기 위해 에이전트 탐지나 상태 보고를 다른 종류로 바꾸지는 않았다.

사용자 확장으로 우회하는 방법도 검토했다. 하지만 herdr-*로 시작하는 사용자 reporter가 있으면 내장 reporter가 일부 필드만 양보하는 것이 아니라 통째로 물러난다. 표시 이름 하나를 바꾸자고 상태 보고 전체를 다시 구현하는 것보다, 값을 잘못 보내는 내장 reporter를 고치는 쪽을 택했다.

시작과 이름 변경을 함께 검사했다

섹션 제목: “시작과 이름 변경을 함께 검사했다”

새 테스트 packages/coding-agent/test/suite/herdr-display-agent.test.ts는 it.each로 브랜드 명령을 omo와 senpi로 바꿔 실행한다. 시작 시와 이름을 바꾼 뒤의 두 pane.report_metadata 요청에서 title은 세션 이름이고 display_agent는 계속 브랜드 명령인지 확인한다. 다음은 핵심 검사 부분이다.

기존 herdr-reporter.test.ts에는 세션 이름을 display_agent의 기대값으로 검사하던 한 줄이 있었다. 그 줄은 title만 검사하도록 바꾸고, 브랜드 라벨 검사는 새 테스트로 옮겼다.

기여 작업에서 herdr 관련 테스트 파일 3개, 테스트 37개가 통과했고 bun run check의 lint, 포맷, 타입 검사도 통과했다. 수정을 잠시 되돌렸을 때 새 테스트가 실패하는 것도 확인했다. 단순히 통과하는 테스트를 추가한 것이 아니라 수정 전 동작을 실제로 잡는지 확인한 것이다. 이 결과는 기여 당시 실행 기록이며, 아래 GitHub의 공개 check 상태와는 구분한다.

수정 커밋은 08bc8004다.

변경 기록은 원본 로그가 아니라 fragment였다

섹션 제목: “변경 기록은 원본 로그가 아니라 fragment였다”

처음에는 해당 확장의 changes.md에 변경 기록을 직접 썼다. 그런데 senpi의 AGENTS.md와 changes/unreleased/README.md에는 다른 규칙이 있었다. senpi#3610에서 도입한 change fragment 방식이다.

PR은 기존 changes.md나 패키지 CHANGELOG.md의 [Unreleased]를 직접 고치지 않는다. 여러 PR이 같은 파일 맨 위를 바꾸면 하나를 머지할 때 다른 PR에서 충돌이 생겼기 때문이다. 대신 PR마다 changes/unreleased/<PR번호>.md 파일 하나를 추가한다.

파일 안에서는 <!-- changes-log: <경로> -->로 어느 로그에 들어갈 내용인지 나눈다. tracker 블록에는 날짜와 네 개의 정해진 절을 쓰고, 패키지 CHANGELOG 블록에는 ### Fixed 같은 분류와 한 줄 요약을 쓴다. 실제 제출한 fragment는 다음과 같다.

파일 이름에 PR 번호가 들어가므로 PR을 연 뒤에 fragment를 만들었다. 기존 로그 수정은 저장소의 변환 스크립트로 되돌리고 같은 내용을 fragment로 옮겼다.

CHANGELOG의 Fixed 한 줄을 더해 77b32916으로 커밋했다. 최종 PR 변경 파일은 index.ts, 테스트 2개, fragment 1개다.

릴리스 때는 scripts/release.mjs가 fragment를 원래 로그에 합치고 지운다. PR별 규칙은 .github/workflows/changelog-gate.yml과 scripts/check-pr-changelog.mjs가 검사한다. 이는 저장소 규칙의 설명이며, 이번 PR에서 해당 gate의 성공 결과까지 확인됐다는 뜻은 아니다.

빈 설정 폴더로 실제 CLI를 띄웠다

섹션 제목: “빈 설정 폴더로 실제 CLI를 띄웠다”

senpi의 AGENTS.md는 Runtime 변경에 scoped test와 bun run check뿐 아니라 실제 CLI QA도 요구한다. 증적은 local-ignore/qa-evidence/<날짜>-<slug>/에 두고 git에 올리지 않는다. PR에는 결정적인 발췌와 파일별 SHA-256을 남기는 방식이다.

설치된 omo는 수정 전 엔진이므로 수정한 소스를 OmO 브랜드로 띄웠다. QA 때 사용한 명령은 다음과 같다. 빈 임시 설정 폴더를 지정해 실제 설정을 건드리지 않았다.

--no-env는 API 키 없이 실행하는 옵션이다. 모델을 호출하지 않아도 세션 시작 때 herdr 보고가 나가므로, 이 버그는 모델 응답 없이 확인할 수 있었다. 실행된 CLI 안에서는 다음과 같이 세션 이름을 바꾸고 pane 메타데이터를 읽었다. !는 셸 명령 실행이다.

기존 pane에 영향을 주지 않도록 포커스를 가져오지 않는 별도 QA workspace를 만들어 사용하고 끝난 뒤 닫았다. 프로젝트 신뢰 질문에는 이번 세션에서 신뢰하지 않는 쪽을 골랐다. 환경은 herdr 0.9.5, macOS arm64였다.

이름 변경 뒤 비교display_agenttitle
수정 전, 설치된 omo 5.1.48QA renameQA rename
수정 후, PR 브랜치omoQA rename

수정 버전은 시작할 때부터 display_agent가 omo였고 이름을 바꾼 뒤에도 유지됐다. 여기서 증적으로 삼은 것은 사이드바 스크린샷이 아니라 herdr가 사이드바 라벨에 사용하는 필드의 출력이다. PR의 QA 댓글에 전후 출력과 로컬 증적 파일별 해시를 남겼다.

현재 PR 상태와 검증 범위

섹션 제목: “현재 PR 상태와 검증 범위”

이 기여는 Claude Code와 함께 진행했다. 처음에는 저장소의 AGENTS.md가 로드되지 않은 상태에서 작업해 changes.md를 직접 고쳤다. 세션을 저장소 안으로 옮겨 규칙을 읽은 뒤에야 fragment 방식임을 알아챘다. 커밋에는 Co-Authored-By 트레일러로 에이전트를 표기했다.
