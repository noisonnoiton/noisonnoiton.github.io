Argo Workflow 기반 CI/CD Task 자동화와 실시간 모니터링

📅 2021-11-10 noisonnoiton

GitOps 기반 플랫폼에서 개발자가 빌드·배포 버튼을 누르는 순간부터 실제 Pod가 떠서 트래픽을 받기까지, 중간의 모든 단계를 자동화하고 그 과정을 실시간으로 보여줘야 한다. 이 글은 Argo Workflow로 Task를 표준화하고, Server-Sent Events로 진행 상황을 스트리밍하는 구조를 다룬다.

Task 유형 분류

섹션 제목: “Task 유형 분류”

플랫폼에서 다루는 Task는 크게 두 가지로 나뉜다.

유형세부설명
CIBuild소스 체크아웃, 이미지 빌드, 레지스트리 푸시
CDDeployNamespace, Deployment, Service, Ingress, HPA
CDResource배포 후 리소스 변경 (replica, resource limit)
CDHelmHelm chart 배포·업그레이드
CDJob일회성 Job, CronJob 스케줄 변경
CDStoragePVC 생성

모든 Task는 Argo WorkflowTemplate로 정의한다. CD manifest는 Git repository에서 관리하며, ArgoCD Application으로 클러스터와 sync한다. 이렇게 하면 Task 실행 이력과 배포 상태가 모두 선언적으로 남는다.

Task Runner 목록

섹션 제목: “Task Runner 목록”
RunnerArgo 타입생성 리소스역할

Application 관리WorkflowApplicationArgoCD App 기반 리소스 삭제

Server-Sent Events로 실시간 상태 스트리밍

섹션 제목: “Server-Sent Events로 실시간 상태 스트리밍”

사용자가 빌드를 시작하면 Workflow 로그, Pod 상태, Event가 실시간으로 화면에 표시되어야 한다. 이를 위해 SSE(Server-Sent Events) 패턴을 사용한다.

SSE Request 흐름

섹션 제목: “SSE Request 흐름”
  • Router API는 내부 클러스터(IC)에 배포되며, SSE Service를 호출한다.
  • SSE API는 CQ(Control/Query) 클러스터에 배포되며, Kubernetes/Argo의 스트림을 SSE로 변환해서 반환한다.
  • 브라우저는 EventSource 객체로 연결을 유지하고, 서버가 보내는 이벤트를 실시간으로 받는다.

SSE로 제공하는 API 목록

섹션 제목: “SSE로 제공하는 API 목록”
API대상용도
Pipeline LogArgo Workflow log streamCI/CD 프로세스 로그 (Workflow 메인 로그)
Pod Listk8s pod list watch애플리케이션 Pod 목록 조회
Pod Metrick8s pod status streamPod CPU/Memory + 상태 실시간 조회
Pod Logk8s pod log stream개별 Pod 로그 스트리밍
Pod Eventk8s event watchPod 생성·재시작·에러 이벤트 (추후 활용)

Service 구조 — Task, Monitoring, Summary 분리

섹션 제목: “Service 구조 — Task, Monitoring, Summary 분리”

플랫폼 API는 세 가지 역할로 분리된다.

Task Service — Workflow 실행과 제어

섹션 제목: “Task Service — Workflow 실행과 제어”
  • Workflow 생성 (submit_workflow)
  • Workflow 목록 조회 (list_workflows)
  • Archived Workflow 목록 조회 (step별 로그)
  • Workflow 취소 (stop_workflow)

Monitoring Service — SSE 스트리밍

섹션 제목: “Monitoring Service — SSE 스트리밍”
  • Workflow 로그 스트림
  • Archived Workflow 로그 파일
  • Workflow 상태 스트림
  • Pod 목록 watch
  • Pod metric 스트림
  • Pod 로그 스트림

Summary Service — 비동기 집계

섹션 제목: “Summary Service — 비동기 집계”
  • Workflow event를 watch해서 CI/CD 최종 상태를 Redis에 저장
  • Pod status를 watch해서 Run 상태를 Redis에 저장
  • 애플리케이션 목록 화면처럼 많은 데이터를 한 번에 보여줘야 하는 경우, 개별 REST API로는 성능이 나오지 않으므로 미리 집계한 데이터를 Redis에서 제공한다.
