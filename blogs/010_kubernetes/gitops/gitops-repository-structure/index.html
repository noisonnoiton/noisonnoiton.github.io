GitOps Repository 구조 설계 — Helm과 Kustomize 조합, Apps-in-App 패턴

📅 2021-11-09 noisonnoiton

Interactive Diagram

새 탭 ↗

GitOps에서 Repository 구조는 단순히 파일 배치 문제가 아니다. chart 버전을 어떻게 관리하고, 클러스터별 설정을 어떻게 분리하며, ArgoCD Application 자체를 어떻게 선언적으로 관리할지가 전부 Repository 구조에 녹아든다. 이 글은 Helm + Kustomize 조합과 Apps-in-App 패턴으로 클러스터를 완전 선언적으로 관리하는 설계를 다룬다.

Cluster Management — 클러스터 설치도 GitOps

섹션 제목: “Cluster Management — 클러스터 설치도 GitOps”

핵심 원칙:

  • Argo CD를 사용해 클러스터 설치에 필요한 모든 컴포넌트를 구성한다.
  • 설치 manifest는 Git repository에서 관리한다.
  • 설치는 ArgoCD app sync로 수행한다.
  • 클러스터에 직접 kubectl apply로 설치하지 않는다 — 수동 설치는 이력이 남지 않고 복구가 어렵다.

Git Manifests 구조 — Helm과 Kustomize 조합

섹션 제목: “Git Manifests 구조 — Helm과 Kustomize 조합”

구조 설명:

  • Helm chart는 버전별 폴더로 관리 — Helm repo를 쓰지 않고 Git에서 chart source를 직접 관리한다. 버전이 필요하면 폴더를 복사해서 차트를 동결시킨다.
  • Kustomize가 Helm template을 실행 — Argo CD는 kustomize build를 먼저 실행하고, Kustomize가 helm template을 호출한다.
  • 클러스터별 설정은 Kustomize values.yaml에 — base chart는 그대로 두고, 클러스터별로 다른 설정만 overlay values에 둔다.
  • common 폴더는 base로 포함 — TLS 인증서처럼 모든 컴포넌트가 공유하는 리소스는 common에 두고 Kustomize base로 참조한다.

ArgoCD Apps-in-App — Application 자체도 Git으로 관리

섹션 제목: “ArgoCD Apps-in-App — Application 자체도 Git으로 관리”

Apps-in-App 패턴:

  • ArgoCD Application은 UI나 CLI로 생성할 수 있지만, Application 자체도 Git repository로 관리하기 위해 Apps-in-App을 사용한다.
  • argocd-app-init이 다른 ArgoCD Application을 생성하는 역할을 한다.
  • 이렇게 하면 ArgoCD Application을 빠르게 복구할 수 있다 — argocd-app-init만 sync하면 나머지 Application이 자동으로 생성된다.

Deploy Repository 구조

섹션 제목: “Deploy Repository 구조”

Cluster 배포용 Repository

섹션 제목: “Cluster 배포용 Repository”

구조 원칙:

  • base 폴더는 chart 파일을 관리하고 chart 버전별로 폴더를 구성한다.
  • template 폴더는 base의 특정(최종) 버전을 사용하도록 설정이 되며, 실제 배포용 파일로 사용한다.
  • 클러스터별 폴더는 배포되는 클러스터를 구분한다.
  • 클러스터 - project - apps/pvcs/jobs 형태로 폴더를 구성한다.
  • 클러스터 폴더와 template 폴더 하위 구조를 일치시켜서 상대 경로 오류를 방지한다.

Cluster Initialize Repository

섹션 제목: “Cluster Initialize Repository”

Initialize Repository 역할:

  • 클러스터 초기 설정에 필요한 CI/CD 도구와 공통 리소스를 배포한다.
  • base 폴더는 chart 버전별로 관리하고, 클러스터별 폴더는 해당 클러스터에 배포할 chart를 선택한다.

배포 흐름

섹션 제목: “배포 흐름”

이 Repository 구조는 chart 버전 동결, 클러스터별 설정 분리, Application 선언적 관리를 모두 해결한다. 새 클러스터를 추가할 때는 클러스터 폴더만 복사하고 argocd-app-init을 sync하면 전체 환경이 재현된다.
