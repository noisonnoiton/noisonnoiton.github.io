Terraform 환경별 프로비저닝 전략

📅 2024-11-04 noisonnoiton

개요

섹션 제목: “개요”

Terraform을 GitHub로 관리하고 GitHub Actions를 통해 인프라 프로비저닝을 자동화할 때, 환경(dev, stg, prd 등)별로 서로 다른 인프라 설정을 효율적으로 관리하려면 몇 가지 구조적인 전략을 쓸 수 있다. 이를 통해 각 환경의 특수성을 유지하면서 코드 재사용성과 관리 용이성을 확보할 수 있다.

방법

1. 폴더 구조 및 모듈화

섹션 제목: “1. 폴더 구조 및 모듈화”

Terraform 코드를 환경별로 분리하는 가장 쉬운 방법은 디렉토리 구조를 통해 각 환경에 대해 별도의 구성 파일을 두는 것이다. 이를 통해 환경 간의 코드 중복을 최소화하면서 공통된 모듈을 재사용할 수 있다.

  • 환경별로 다른 구성이 필요한 부분은 해당 환경의 폴더에서 정의하고, 공통 부분은 모듈로 분리해 중복을 최소화한다.

2. 환경별 변수 파일 사용 (Variables and Workspaces)

섹션 제목: “2. 환경별 변수 파일 사용 (Variables and Workspaces)”

각 환경에 맞는 구성을 변수 파일로 정의한 후, GitHub Actions에서 환경별로 다른 변수 파일을 선택해 프로비저닝한다. 이를 통해 환경별로 인프라 크기나 네트워크 설정 같은 차이를 관리할 수 있다.

3. Terraform Workspaces 사용

섹션 제목: “3. Terraform Workspaces 사용”

4. GitHub Actions에서 환경 분기 처리

섹션 제목: “4. GitHub Actions에서 환경 분기 처리”

GitHub Actions에서 환경에 따라 다르게 실행하도록 분기 처리를 할 수 있다. 예를 들어 dev, stg, prd와 같은 입력값에 따라 각각 다른 인프라 설정 파일을 사용할 수 있다.

전략 선택 기준

섹션 제목: “전략 선택 기준”
전략상태 파일 분리코드 분리적합한 상황
폴더 구조 + 모듈화완전 분리(디렉토리별 backend)환경별 디렉토리환경 간 리소스 구성 차이가 크고, 완전한 격리가 필요할 때
환경별 변수 파일코드 구조에 따라 다름코드는 공유, 값만 분리환경 간 차이가 인스턴스 크기/리전 정도로 단순할 때
Terraform WorkspacesWorkspace별 state 자동 분리코드 완전 공유코드 중복을 최소화하고 싶고, 환경 수가 유동적일 때
GitHub Actions 매트릭스 분기전략 조합에 따라 다름파이프라인 실행 자체를 병렬 분기여러 환경을 한 워크플로우 실행에서 동시에 처리하고 싶을 때

요약

섹션 제목: “요약”
  • 폴더 구조 및 모듈화: 환경별 폴더 구조와 공통 모듈을 사용해 관리한다.
  • 변수 파일 사용: 환경별로 서로 다른 변수 설정을 사용한다.
  • Terraform Workspaces: 상태 파일을 구분해 동일한 코드에서 다양한 환경을 관리한다.
  • GitHub Actions를 활용한 분기 처리: CI/CD 파이프라인에서 환경에 따른 분기 처리로 유연한 배포가 가능하다.

네 가지 전략은 상호 배타적이지 않으며, 실제로는 “폴더 구조 + 변수 파일” 또는 “Workspaces + Actions 매트릭스”처럼 조합해서 쓰는 경우가 많다. 환경 수가 적고 구성 차이가 단순하면 변수 파일 전략만으로 충분하고, 조직·구독 단위로 상태를 완전히 격리해야 한다면 폴더 구조 분리를 기본으로 가져가는 것이 안전하다.
