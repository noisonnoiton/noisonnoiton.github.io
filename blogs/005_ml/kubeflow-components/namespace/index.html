Namespace (kubeflow / kubeflow-system)

📅 2026-07-07 noisonnoiton

비공개 저장소 참조

이 글은 개인 GitOps 저장소의 manifest와 overlay 구조를 근거로 작성했다. 해당 저장소는 공개하지 않으므로 본문의 저장소 link는 접근되지 않는다. 설계 의도와 구조는 본문만으로 이해할 수 있도록 정리했다.

기본 정보

섹션 제목: “기본 정보”
항목값

공식 문서Kubernetes Namespaces, Pod Security Standards
upstream 소스common/kubeflow-namespace/base

Kubeflow 에서의 역할

섹션 제목: “Kubeflow 에서의 역할”

Kubeflow 의 거의 모든 component 는 공용 namespace kubeflow(그리고 전환 중인 kubeflow-system) 안에서 동작한다. 이 namespace 가 없으면 이후 어떤 component 도 배포될 곳이 없으므로, 이것이 플랫폼의 가장 밑바닥 토대다. 단순히 이름만 만드는 것이 아니라, 그 위에 올라올 모든 workload 의 보안과 네트워크 기본값을 label 과 policy 로 미리 정한다.

  • control plane 의 위치: Dashboard, Profiles controller, Notebooks controller, Katib, KServe controller, Pipelines 등 플랫폼 관리 component 가 kubeflow namespace 에 모인다.
  • mesh 자동 편입: istio-injection: enabled label 로 이 namespace 의 Pod 가 생성될 때 Istio sidecar 가 자동 주입되어 mTLS 와 인가 policy 의 대상이 된다.
  • Pod 보안 기준: pod-security.kubernetes.io/enforce: restricted 로 이 namespace 에 뜨는 Pod 에 가장 엄격한 PodSecurity 표준을 강제한다.
  • 기본 네트워크 격리: NetworkPolicy 로 같은 namespace 내 통신만 기본 허용하고, Kubernetes API server 의 webhook 접근과 istio-system 으로부터의 필요한 traffic 만 예외로 연다.

배포 구조

섹션 제목: “배포 구조”

overlay overlays/dev/kubeflow-namespace 가 common/kubeflow-namespace/base 를 그대로 참조한다. 별도 patch 는 없다. 배포 순서상 가장 먼저 적용되는 토대이며 선행 의존이 없다.

의존성과 상호작용

섹션 제목: “의존성과 상호작용”
  • 선행: 없음. 이 단계가 배포 순서의 시작점이다.
  • 후행 (이 namespace 에 배포됨): 사실상 모든 component. kubeflow 에는 Dashboard, Profiles, Notebooks, Katib, KServe controller, Pipelines 등이 배포되고, kubeflow-system 에는 Trainer 가 배포된다.
  • 런타임 상호작용: istio-injection label 때문에 이 namespace 의 Pod 는 생성 시 sidecar 가 주입되어 mesh 에 합류한다. PodSecurity restricted 가 Pod spec(권한, volume 등)을 제약하며, NetworkPolicy 가 inbound traffic 을 통제한다.

핵심 리소스

섹션 제목: “핵심 리소스”
  • Namespace label 3종: istio-injection: enabled(mesh 편입), pod-security.kubernetes.io/enforce: restricted(PSS 강제), control-plane: kubeflow(control plane 식별).
  • NetworkPolicy set: 기본은 같은 namespace 통신만 허용하고, 각 component 의 mutating webhook(cache-server, jupyter-web-app, katib-controller, kserve, training-operator 등)에 대해 API server 와 istio-system 의 접근만 열어 최소 권한 네트워크를 구성한다.
  • 이 namespace 가 확립되어야 이후 단계가 Pod 를 배치할 수 있으므로, 배포 순서상 반드시 선행되어야 한다.
