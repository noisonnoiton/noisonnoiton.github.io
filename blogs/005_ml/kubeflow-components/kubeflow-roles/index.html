Kubeflow Roles (aggregated RBAC)

📅 2026-07-15 noisonnoiton

비공개 저장소 참조

이 글은 개인 GitOps 저장소의 manifest와 overlay 구조를 근거로 작성했다. 해당 저장소는 공개하지 않으므로 본문의 저장소 link는 접근되지 않는다. 설계 의도와 구조는 본문만으로 이해할 수 있도록 정리했다.

기본 정보

섹션 제목: “기본 정보”
항목값
version해당 없음 (community-distribution release-26.03.1 의 Kubeflow 기본 ClusterRole)
공식 문서Kubernetes RBAC, ClusterRole Aggregation
upstream 소스common/kubeflow-roles/base

개념과 특징

섹션 제목: “개념과 특징”

Kubeflow 는 사용자별 Profile namespace 를 만들고, 그 namespace 안에서 사용자가 Notebook, Pipeline, InferenceService 같은 리소스를 다루도록 권한을 부여한다. 이때 모든 app 권한을 하나의 거대한 Role에 직접 적지 않고, Kubernetes ClusterRole aggregation을 사용한다. kubeflow-admin, kubeflow-edit, kubeflow-view는 빈 그릇이고, 특정 label을 가진 다른 ClusterRole의 rules가 Kubernetes controller에 의해 자동으로 합쳐진다.

보통 ClusterRole은 권한을 rules에 직접 적지만, 이 기준 role들은 rules가 비어 있고 label 조건(aggregationRule)만 가진다. Kubernetes의 RBAC aggregation controller가 그 label이 붙은 다른 ClusterRole의 rules를 찾아 이 빈 role 안으로 자동 복사한다. 그래서 component는 자기 ClusterRole에 label 한 줄만 붙이면, 중앙 role을 수정하지 않고도 권한이 흡수된다.

component 가 확립하는 것

섹션 제목: “component 가 확립하는 것”
  • 기준 ClusterRole 3종: kubeflow-admin, kubeflow-edit, kubeflow-view. 각 역할은 aggregationRule만 가진다.
  • 기본 Kubernetes 권한 3종: kubeflow-kubernetes-admin, kubeflow-kubernetes-edit, kubeflow-kubernetes-view. Pod, Deployment, Service, PVC, Secret, NetworkPolicy 같은 일반 Kubernetes 리소스에 대한 admin/edit/view 권한을 제공한다.
  • 상속 구조: kubeflow-view는 kubeflow-edit에 합쳐지고, kubeflow-edit는 kubeflow-admin에 합쳐진다. 따라서 admin은 edit/view 계층의 권한을 포함한다.

Kubeflow 에서의 역할

섹션 제목: “Kubeflow 에서의 역할”

배경

섹션 제목: “배경”

Profile controller와 KFAM은 사용자를 Profile namespace에 연결할 때 Kubeflow 역할을 기준으로 RoleBinding을 만든다. 이 단계의 ClusterRole이 없으면 이후 component가 자기 권한을 label로 확장해도 합쳐질 대상이 없다. 즉 이 component는 사용자 namespace RBAC의 공통 어휘를 먼저 만든다.

핵심 기여

섹션 제목: “핵심 기여”
  • multi-tenancy 권한 기준: 사용자가 자기 Profile namespace 안에서 무엇을 볼 수 있고, 만들 수 있고, 관리할 수 있는지의 기본 계층을 제공한다.
  • component 권한 확장 지점: Istio, Knative, KServe, Katib, Pipelines, Notebooks, Trainer 등이 각자의 ClusterRole에 aggregate-to-kubeflow-* label을 붙여 이 기준 역할에 권한을 추가한다.
  • Profile owner 권한의 기반: Profile이 reconcile되면 owner와 기본 ServiceAccount에 namespace 범위 RoleBinding이 생기는데, 그 RoleBinding이 참조할 수 있는 공통 ClusterRole 체계가 이 단계에서 준비된다.

배포 구조

섹션 제목: “배포 구조”

overlay 구성

섹션 제목: “overlay 구성”

overlays/dev/kubeflow/common/roles가 common/kubeflow-roles/base를 그대로 참조한다. 별도 patch는 없다.

이 단계는 workload를 만들지 않는다. namespace에도 종속되지 않는 cluster-scoped RBAC 리소스만 만든다.

aggregation label 규칙

섹션 제목: “aggregation label 규칙”
합쳐지는 대상selector label대표 제공자
kubeflow-adminrbac.authorization.kubeflow.org/aggregate-to-kubeflow-admin: "true"kubeflow-kubernetes-admin, kubeflow-istio-admin, component 별 admin role
kubeflow-editrbac.authorization.kubeflow.org/aggregate-to-kubeflow-edit: "true"kubeflow-kubernetes-edit, kubeflow-kserve-edit, component 별 edit role
kubeflow-viewrbac.authorization.kubeflow.org/aggregate-to-kubeflow-view: "true"kubeflow-kubernetes-view, kubeflow-kserve-view, component 별 view role

kubeflow-edit 자체에는 aggregate-to-kubeflow-admin: "true" label이 붙고, kubeflow-view 자체에는 aggregate-to-kubeflow-edit: "true" label이 붙는다. 이 label 때문에 view 권한은 edit로, edit 권한은 admin으로 단계적으로 포함된다.

의존성과 상호작용

섹션 제목: “의존성과 상호작용”

선행 / 후행

섹션 제목: “선행 / 후행”
  • 선행: 없음. cluster-scoped RBAC만 만들기 때문에 namespace나 workload가 없어도 적용 가능하다.
  • 후행 (이 역할을 확장): kubeflow-istio-resources, Knative, KServe, Katib, Pipelines, Notebooks, Trainer 등 component 별 user-facing ClusterRole.
  • 후행 (이 역할을 바인딩): Dashboard/Profiles/KFAM과 user Profile. Profile reconcile 이후 사용자는 자기 namespace에서 이 기준 role을 통해 권한을 받는다.

런타임 상호작용

섹션 제목: “런타임 상호작용”

이 component 자체는 Pod를 만들지 않는다. Kubernetes RBAC aggregation controller가 label selector를 계속 평가하면서 kubeflow-admin, kubeflow-edit, kubeflow-view의 effective rules를 갱신한다. 이후 새 component가 설치되어 aggregate-to-kubeflow-view 같은 label을 가진 ClusterRole이 추가되면, 별도 수동 병합 없이 기존 Kubeflow role에 권한이 반영된다.

핵심 리소스

섹션 제목: “핵심 리소스”
  • kubeflow-admin / kubeflow-edit / kubeflow-view: 사용자가 직접 참조하는 기준 ClusterRole. rules는 비어 있고 aggregationRule로 구성된다.
  • kubeflow-kubernetes-admin: namespace 안의 Role/RoleBinding 관리와 LocalSubjectAccessReview 생성 권한을 admin 계층에 제공한다.
  • kubeflow-kubernetes-edit: Pod exec/portforward, Secret, Service, PVC, Deployment, Job, NetworkPolicy 등 일반 namespace 리소스에 대한 쓰기 권한을 edit 계층에 제공한다.
  • kubeflow-kubernetes-view: Pod, log, Service, PVC, workload status, event 등 일반 namespace 리소스의 조회 권한을 view 계층에 제공한다.
