Dashboard (Central Dashboard + Profiles + PodDefaults)

📅 2026-07-17 noisonnoiton

비공개 저장소 참조

이 글은 개인 GitOps 저장소의 manifest와 overlay 구조를 근거로 작성했다. 해당 저장소는 공개하지 않으므로 본문의 저장소 link는 접근되지 않는다. 설계 의도와 구조는 본문만으로 이해할 수 있도록 정리했다.

기본 정보

섹션 제목: “기본 정보”
항목값
version해당 없음 (community-distribution release-26.03.1 의 dashboard manifests)
공식 문서Kubeflow Central Dashboard, Profiles
upstream 소스applications/dashboard

개념과 특징

섹션 제목: “개념과 특징”

이 단계는 이름은 Dashboard지만 단순 UI 하나만 설치하지 않는다. Kubeflow 사용자가 로그인 후 보는 Central Dashboard, Profile CR을 reconcile하는 controller, Notebook Pod 생성 시 PodDefault를 적용하는 admission webhook이 함께 들어온다. 그래서 이 단계가 끝나야 “로그인한 사용자에게 어떤 namespace가 보이고, 그 namespace에서 Notebook에 기본 설정을 주입할 수 있는가”의 기반이 생긴다.

component 가 확립하는 것

섹션 제목: “component 가 확립하는 것”
  • Central Dashboard: / 경로를 잡는 Kubeflow web app. 메뉴 링크와 quick link를 제공하고, profiles-kfam을 호출해 사용자가 접근 가능한 namespace 목록을 표시한다.
  • Profile controller / KFAM: Profile CRD와 controller. Profile을 reconcile해 사용자 namespace, RoleBinding, 기본 ServiceAccount, Istio AuthorizationPolicy 등을 만든다. KFAM은 Dashboard가 namespace membership을 조회/관리할 때 쓰는 service다. 별도 Deployment가 아니라 profiles-deployment Pod 안의 두 번째 container(kfam)로 동작하고, profiles-kfam은 그 앞의 Service로만 존재한다.
  • PodDefaults webhook: PodDefault CRD와 mutating admission webhook. Notebook Pod에 selector 기반으로 env, volume, volumeMount 같은 기본 설정을 주입한다.

Kubeflow 에서의 역할

섹션 제목: “Kubeflow 에서의 역할”

배경

섹션 제목: “배경”

Kubeflow multi-tenancy의 중심은 Profile이다. 사용자는 전체 클러스터를 직접 쓰는 것이 아니라 자기 Profile namespace에서 Notebook, Pipeline, InferenceService 같은 리소스를 만든다. Dashboard는 이 namespace들을 UI로 보여 주고, Profile controller는 실제 namespace와 권한을 만든다. PodDefaults webhook은 Notebook UX를 구성하는 부가 설정을 Pod 생성 시점에 주입한다.

핵심 기여

섹션 제목: “핵심 기여”
  • 사용자 진입 화면: root path(/)를 Central Dashboard로 routing한다. 이후 Notebooks, Pipelines, Katib, KServe, Model Registry 같은 app은 dashboard 메뉴를 통해 접근한다.
  • Profile lifecycle 기반: profiles.kubeflow.org CRD와 controller를 설치해 다음 단계의 예제 Profile(kubeflow-user-example-com)을 reconcile할 준비를 한다.
  • namespace membership API: Dashboard가 profiles-kfam service를 통해 현재 사용자(kubeflow-userid)의 namespace 접근 권한을 확인한다.
  • Notebook 기본값 주입: poddefaults.kubeflow.org CRD와 mutating webhook을 설치해, Notebook Pod에 사용자 선택형 기본 설정을 주입할 수 있게 한다.

배포 구조

섹션 제목: “배포 구조”

overlay 구성

섹션 제목: “overlay 구성”

overlays/dev/kubeflow/overlays/dashboard 는 applications/dashboard/overlays/istio 를 그대로 참조한다. dev overlay 자체 patch는 없다.

applications/dashboard/overlays/istio 에서는 dashboard-config ConfigMap을 patch해 Kubeflow 메뉴를 구성한다. Notebooks, TensorBoards, Volumes, Katib, KServe Endpoints, Model Registry, Pipelines 링크가 여기서 정의된다.

Profile namespace label

섹션 제목: “Profile namespace label”

kubeflow-pss overlay는 Profile namespace에 붙일 label set을 ConfigMap으로 제공한다.

label값의미
app.kubernetes.io/part-ofkubeflow-profileProfile namespace 식별
katib.kubeflow.org/metrics-collector-injectionenabledKatib metrics collector 주입
pipelines.kubeflow.org/enabledtrueKFP multi-user namespace 활성화
serving.kubeflow.org/inferenceserviceenabledKServe InferenceService 사용 namespace
pod-security.kubernetes.io/enforcebaselineProfile namespace PodSecurity 기준

주의할 점은 Profile controller가 이미 존재하는 label을 덮어쓰지 않는다는 점이다. 이미 생성된 namespace의 label 값을 바꾸려면 label 제거 후 다시 추가해야 한다. 이 저장소의 예제 Profile overlay는 retry하는 별도 Job으로 PodSecurity label을 보정한다. 그 상세는 다음 08-user-profile 문서에서 다룬다.

의존성과 상호작용

섹션 제목: “의존성과 상호작용”

선행 / 후행

섹션 제목: “선행 / 후행”
  • 선행: kubeflow-namespace, cert-manager, istio, oauth2-proxy, dex, kubeflow-istio-resources, kubeflow-roles.
  • 후행: 08-user-profile(Profile CR apply), Notebooks, Pipelines, Katib, KServe, Model Registry 등 dashboard menu와 Profile namespace에 의존하는 component.

런타임 상호작용

섹션 제목: “런타임 상호작용”

브라우저 요청은 auth-flow를 통과해 kubeflow-userid header를 가진 상태로 Dashboard에 도달한다. Dashboard는 그 신원을 기준으로 profiles-kfam에 namespace membership을 조회한다. Profile controller는 Profile CR을 watch하다가 새 Profile이 생기면 namespace와 기본 권한을 reconcile한다. Notebook Pod가 생성될 때는 PodDefaults webhook이 같은 namespace의 PodDefault를 조회해 selector에 맞는 설정을 주입한다.

핵심 리소스

섹션 제목: “핵심 리소스”
  • centraldashboard Deployment/Service/VirtualService: Kubeflow root UI. dashboard-config가 메뉴와 quick link를 정한다.
  • profiles.kubeflow.org CRD + profiles-deployment: Profile namespace reconcile의 중심. 다음 단계에서 apply되는 예제 Profile이 이 controller에 의해 namespace로 구체화된다.
  • profiles-kfam Service/VirtualService/AuthorizationPolicy: Dashboard가 쓰는 Profile membership 관리 API. 실제 process는 profiles-deployment Pod의 kfam container이고, profiles-kfam은 그 container를 가리키는 Service로만 존재한다.
  • poddefaults.kubeflow.org CRD + webhook: Notebook Pod에 기본 설정을 주입하는 admission path.
  • poddefaults-webhook-cert: cert-manager가 발급하고 webhook이 사용하는 TLS certificate. caBundle 주입은 cert-manager/cainjector가 처리한다.
