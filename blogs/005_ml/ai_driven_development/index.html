AI 기반 개발: 요구사항에서 PR Review까지

📅 2025-07-29 noisonnoiton

이 시리즈는 AI Coding Assistant를 도구 하나로 다루지 않는다. 대신 요구사항이 들어와서 사람이 승인한 Pull Request로 나가기까지, 하나의 요구사항이 어떤 Artifact로 변환되는지를 따라간다.

이 시리즈가 다루지 않는 것도 분명히 밝힌다. 이 글들은 n8n이나 Backstage로 Agent Platform을 구축하는 방법을 다루지 않는다(그 내용은 Agent Builder에 있다). 또한 CI/CD Pipeline이나 Kubernetes 위에서 Test를 실행하는 방법도 다루지 않는다(그 내용은 Platform Engineering에 있다). 이 시리즈의 관심사는 AI가 Software Delivery Lifecycle 안에서 무엇을 만들고, 사람이 무엇을 검증하며, 그 경계가 어디에 있는지다.

Artifact Chain

섹션 제목: “Artifact Chain”

시리즈 전체를 관통하는 흐름은 다음과 같다.

각 화살표는 이 시리즈의 한 편에 대응한다. 앞 단계를 건너뛰면 뒤 단계는 검증할 근거를 잃는다 — Architecture Decision 없이 만든 코드는 무엇을 기준으로 리뷰해야 할지 알 수 없고, Acceptance Criteria 없이 만든 Test는 무엇을 확인했는지 증명할 수 없다.

읽는 순서

섹션 제목: “읽는 순서”

Foundations

섹션 제목: “Foundations”
Agile Delivery와 AI의 Role Boundary AI가 Delivery의 어느 단계에서 초안을 만들 수 있고, 어느 결정은 항상 사람에게 남아야 하는지를 Discovery/Delivery/Transition과 Human Gate로 정리한다

Discovery & Planning

섹션 제목: “Discovery & Planning”
요구사항을 AI-ready Artifact로 변환하기 모호한 Raw Requirement를 명시적 요구사항, 가정, 미해결 질문으로 분리하고 Architecture Decision까지 도출하는 과정
PRD와 UI Artifact에서 검증 가능한 User Story 만들기 PRD와 화면 설계가 각각 알려줄 수 있는 것과 없는 것을 구분하고, Given-When-Then 기반 Acceptance Criteria로 Story를 검증 가능하게 만드는 방법
Coding Agent를 위한 Context Package 설계 Task/Context/Constraints/Acceptance로 구조화된 입력이 자연어 프롬프트보다 나은 이유와 Agent 출력 규격

Development & Quality

섹션 제목: “Development & Quality”
User Story에서 Test Scenario와 Test Code까지 코드가 없을 때의 Document-first 시나리오와, 코드가 생긴 뒤의 Code-grounded 보정을 구분하는 Two-pass Test Design
AI-assisted PR Note와 Code Review AI가 PR Summary와 Review를 도울 수 있는 부분과, Business/Security/Release 승인처럼 절대 넘길 수 없는 부분을 구분한다

이 시리즈의 전제

섹션 제목: “이 시리즈의 전제”

모든 예시는 가상의 Event Registration(행사 등록) 서비스를 기준으로 한다. 실제 조직, 실제 시스템, 실제 화면을 옮기지 않는다. 원본 자료를 인용하는 대신, 그 자료가 보여준 문제를 다시 설계해서 설명한다.
