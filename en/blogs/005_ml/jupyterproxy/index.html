Jupyter Server Proxy

📅 2021-05-30 noisonnoiton

Private repository reference

This article is based on the manifests and overlay structure of a personal GitOps repository. That repository is not public, so the repository links in this article are not accessible. The design intent and structure are written to be understandable from this article alone.

Introduction

Section titled “Introduction”

With Jupyter Server Proxy, you can run arbitrary external processes—such as RStudio or VS Code—alongside a notebook server and let the notebook server handle authentication on their behalf.

After installing the jupyter-server-proxy extension in a Notebook or JupyterLab environment, you can expose those processes through proxy URLs and launch them directly from the browser UI.

  • Run from the Jupyter Notebook Extension
  • Run from the Jupyter Hub Extension

See Jupyter Server Proxy Docs https://jupyter-server-proxy.readthedocs.io/en/latest/index.html

Running nonjupyter applications on JupyterHub with jupyter-server-proxy| JupyterCon 2020 https://www.youtube.com/watch?v=8tFLZWT0u2Y

Setup with Jupyter Hub

Section titled “Setup with Jupyter Hub”

Assume JupyterHub is running and that a process on the user’s notebook server is listening on port 8080. In that case, the service can be reached through the JupyterHub URL—for example, myhub.org/hub/{user-redirect}/proxy/8080.

JupyterHub redirects each authenticated user to the correct per-user URL. You can also use the default_url setting to land users directly in the proxied application. If a user is not logged in, authentication happens first and the browser is redirected afterward.

  • Architecture

Customization

Section titled “Customization”

The main customization work is deciding how to package applications such as code-server and RStudio so they run beside the notebook process and can be exposed through the Jupyter proxy.

Code Server by Jupyter Proxy

Section titled “Code Server by Jupyter Proxy”
  • Work covered here
    • Build a code-server base image on top of a Jupyter notebook image
    • Create and copy VS Code settings
    • Create and copy jupyter_notebook_config.py
    • Add a jupyter-code-server profile and KubeSpawner settings to the JupyterHub profile list

kloudbank Github Repository https://github.com/kloudbank/jupyter-k8s/tree/main/dev/jupyter-notebook/code-server

Create Base Image

Section titled “Create Base Image”
  • Dockerfile composition
    • Start from the official jupyter/minimal-notebook image
    • Install jupyter-server-proxy into the conda environment
    • Enable the server extension and lab extension
    • Install Linux code-server
    • Copy the VS Code and Jupyter configuration directories

jupyter server proxy config

Section titled “jupyter server proxy config”
  • Create jupyter_notebook_config.py
    • Define the launch command, launcher entry, and URL mapping for the proxied application.
    • From JupyterHub’s point of view this is still a notebook server, so the notebook behavior is configured through NotebookApp while the proxy mapping itself is configured through ServerProxy.

Section titled “Jupyter Hub Config Settings”

Developing a Web App. in Jupyter Code Server

Section titled “Developing a Web App. in Jupyter Code Server”

Once the Jupyter-based code-server image is running, you can also expose a local web service through the proxy by referencing its port in the URL.

  • flask python code example
  • Run in Jupyter Code Server

  • Specify port 5000 in the URL, and call it from the Web Browser through the Jupyter Server Proxy : ex> myhub.org/hub/{user-redirect}/proxy/5000

R Studio by Jupyter Proxy

Section titled “R Studio by Jupyter Proxy”

For RStudio, the open-source jupyter-rsession-proxy package already provides most of the required integration, so a separate notebook-level proxy configuration is not necessary.

  • Work covered here
    • Build an RStudio base image on top of a Jupyter notebook image
    • Install jupyter-rsession-proxy in that base image
    • Add an RStudio profile and KubeSpawner settings to the JupyterHub profile list

kloudbank Github Repository https://github.com/kloudbank/jupyter-k8s/tree/main/dev/jupyter-notebook/rstudio

Create Base Image

Section titled “Create Base Image”
  • Dockerfile composition
    • Based on the Jupyter minimal-notebook Official Image
    • Install the jupyter-rsession-proxy package in the Conda environment
    • Install R Studio

jupyter-rsesssion-proxy

Section titled “jupyter-rsesssion-proxy”

  • jupyter-rsession-proxy package notes

    • The package already defines the rstudio-server and rsession launch behavior required to run RStudio.
    • The ServerProxy configuration for /rstudio is included, so no additional notebook config is needed.

  • package setup.py

See jupyter-rsession-proxy Github Repository https://github.com/jupyterhub/jupyter-rsession-proxy
