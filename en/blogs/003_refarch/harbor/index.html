What is Harbor?

Harbor?

Section titled “Harbor?”

(Source: https://goharbor.io/)

Harbor is an open-source registry that secures artifacts with policy and role-based access control, ensures images are scanned and free from vulnerabilities, and signs images as trusted. As a CNCF (Cloud Native Computing Foundation) Graduated project, Harbor delivers compliance, performance, and interoperability to help you consistently and securely manage artifacts across cloud-native computing platforms such as Kubernetes and Docker.

(CNCF project maturity levels, Source: https://www.cncf.io/projects/)

(Source: https://landscape.cncf.io/?category=container-registry&grouping=category)

Section titled “Architecture Overview”

(Source: https://github.com/goharbor/harbor/wiki/Arch%E3%85%81itecture-Overview-of-Harbor)

Main Feature

Section titled “Main Feature”

(Source: https://goharbor.io/)

  • Security and vulnerability analysis
    • Harbor regularly scans images to check for vulnerabilities and performs policy checks to prevent vulnerable images from being deployed.
  • Content signing and validation
  • Multi-tenant
  • Extensible API and web UI
  • Image replication across multiple Harbor instances
    • You can replicate (synchronize) images and charts between multiple registry instances based on policies that use filters (repository, tag, label). Harbor automatically retries replication when an error occurs. This can be used to support load balancing, achieve high availability, and facilitate multi-datacenter deployments in hybrid and multi-cloud scenarios.
  • Identity integration and role-based access control(RBAC) : You can grant user permissions separately per project, and actions are restricted according to those permissions.

(Source: https://github.com/goharbor/harbor/blob/master/docs/user_guide.md#role-based-access-controlrbac)

Why Harbor?

Section titled “Why Harbor?”

public vs. private

Section titled “public vs. private”

There are two types of container registries: public and private.

- A public registry is basic in terms of abilities/offerings and easy to use, making it suitable for individuals or small teams who want to get a registry up and running as quickly as possible. However, as the scale grows, security issues such as patching, privacy, and access control may arise.

- A private registry provides a way to integrate security and privacy into enterprise container image storage that is hosted remotely or on-premises. A company can choose to build and deploy its own container registry or choose a commercial private registry service. Such private registries often come with advanced security features and technical support.

Configuring Redundancy

Section titled “Configuring Redundancy”

Among the features officially supported by Harbor, there is “Configuring Replication”.

This synchronizes resources (images, charts, etc.) between multiple registries.

When a Harbor system administrator configures a Replication Rule, all resources matching the defined filter pattern are replicated to the target registry when the trigger condition is met.

cf) However, in actual production environments, you often need to mirror to release tens or hundreds of cluster nodes. In this case, a single download registry cannot meet the demands of many nodes, so you configure multiple instance registries to perform load balancing.

As shown above, Harbor supports replication of various registries.

I configured one more harbor Registry in advance (harbor2), and registered the existing harbor’s endpoint in harbor2

Once you’ve registered the endpoint, enter the Replications menu and try creating a Rule.

You can see that the endpoint you just registered appears in the Destination registry (the registry to synchronize data to).

push-based and pull-based determine whether to replicate from another registry or replicate to another registry when replicating an artifact. (Official Harbor docs: Select Push-based or Pull-based replication, depending on whether you want to replicate artifacts to or from the remote registry.)

Once you’ve registered it this way, the data is synchronized with the existing harbor each time an image is pushed to harbor2 as shown below.

Image push to harbor2

kmchoi-test was also pushed to the existing harbor.

However, registering the existing harbor Registry in harbor2 only means one-way synchronization from harbor2->harbor,

so if you want two-way synchronization, you must also create a Rule with the harbor2 Registry in harbor.
