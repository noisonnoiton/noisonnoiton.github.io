GitOps and ArgoCD Overview

📅 2024-10-15 noisonnoiton

Overview

Section titled “Overview”

GitOps is an approach that uses Git as the Single Source of Truth to manage the state of applications and infrastructure declaratively. While the 006_gitops series covered real deployment pipelines and operational tools such as Flagger and Argo Workflow, this article covers the introductory-level GitOps/ArgoCD concepts distilled from an organization’s standard architecture documentation. Think of it as the standard reference material used to introduce GitOps to a new team.

Key Concepts

Section titled “Key Concepts”
  1. Declarative configuration: The state of infrastructure and applications is defined in declarative files such as YAML/JSON.
  2. Git as the single source of truth: All configuration files are stored in a Git repository, and version control tracks the change history.
  3. Automated synchronization: The state in the Git repository is automatically synchronized with the actual cluster state, using tools such as ArgoCD or Flux.
  4. Auditing and rollback: Git’s change history lets you trace who changed what and when, and roll back to a previous state when needed.

Advantages of GitOps

Section titled “Advantages of GitOps”
  • Version control: Every change is recorded in Git, making the change history easy to trace.
  • Automation: Declarative configuration combined with automated synchronization reduces manual work and guarantees consistent deployments.
  • Collaboration: Git-based code review and approval processes make cross-team collaboration easier.
  • Stability: Declarative configuration and automated synchronization keep the state of infrastructure and applications consistent.

GitOps Workflow

Section titled “GitOps Workflow”
  1. Write configuration files: Author declarative configuration files for the application and infrastructure.
  2. Commit to the Git repository: Commit and push the configuration files to the Git repository.
  3. Set up the automation tool: Use a GitOps tool such as ArgoCD or Flux to synchronize the Git repository with the cluster.
  4. Automatic synchronization: The GitOps tool detects changes in the Git repository and automatically updates the cluster state.
  5. Monitoring and rollback: Monitor changes and roll back to a previous state when needed.

ArgoCD Architecture

Section titled “ArgoCD Architecture”

ArgoCD is a Kubernetes-native GitOps tool that uses a Git repository as the single source of truth to automatically deploy and manage applications on a Kubernetes cluster.

ArgoCD’s key components are as follows.

  • API Server: Provides ArgoCD’s core API and is used to interact through the web UI and CLI.
  • Repository Server: Interacts with the Git repository to fetch the application’s declarative configuration.
  • Application Controller: Monitors application state and synchronizes state between the Git repository and the Kubernetes cluster.
  • Dex: Supports SSO (Single Sign-On) and OAuth2 authentication.
  • Notification Server: Provides notifications for events such as application state changes, sync status, and health check results.
  • Redis: Handles caching and session management to improve performance.

Key Features

Section titled “Key Features”
  • Automatic sync: Detects changes in the Git repository and automatically updates the Kubernetes cluster state.
  • Declarative configuration: Declaratively defines application state as YAML or JSON files.
  • Web UI and CLI: Provides a user-friendly web UI and a powerful CLI.
  • RBAC: Manages user permissions through role-based access control.
  • Health checks and rollback: Monitors application state and rolls back to a previous state when needed.
  • Multi-cluster support: Can manage multiple Kubernetes clusters.

Summary

Section titled “Summary”

GitOps is an approach that uses Git as the single source of truth to declaratively manage applications and infrastructure. ArgoCD implements this approach through six axes of components — the API server, repository server, application controller, Dex, notification server, and Redis — and streamlines the deployment and operation of Kubernetes applications through features such as automatic synchronization, RBAC, and multi-cluster support.
