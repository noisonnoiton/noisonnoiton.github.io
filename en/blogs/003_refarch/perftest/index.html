Redis Performance Measurement

📅 2021-04-07 noisonnoiton

Prerequisite

Section titled “Prerequisite”
  • Deploy nGrider Controller on EKS https://github.com/kloudbank/session-k8s/tree/main/dev/ngrinder/controller
  • Deploy nGrider Agent on EKS https://github.com/kloudbank/session-k8s/tree/main/dev/ngrinder/agent
  • EKS Cluster Monitoring via Prometheus and Grafana http://k8s-grafana-grafana-6380e9e544-711314603.ap-northeast-2.elb.amazonaws.com/?orgId=1

Redis-Benchmark

Section titled “Redis-Benchmark”

A performance measurement tool that Redis provides itself for RedisCluster and Sentinel setups.

  • aof:no
  • aof:yes, aofsync:everysec
  • aof:yes, aofsync:always

nGrinder

Section titled “nGrinder”

Developed by Naver, this is a stress test tool that can simultaneously run script generation / test execution / monitoring and result report generation. http://naver.github.io/ngrinder/

AOF everysec vs always

Section titled “AOF everysec vs always”
  • See the Redis Persistence explanation http://redisgate.kr/redis/configuration/persistence.php
  • Based on the benchmark above and the nGrinder load test results, when the Redis instance’s resources stay stable, there is no significant performance difference even when persisting data
    • To verify the performance difference during persistence, an extreme load test was conducted

Load Test

Section titled “Load Test”
  • Environment
    • Resources minimized so that CPU is at 100% usage
    • Increased the size of the existing SET data (1 row) by 100
    • Increased so that a lot of memory can be used to persist data
