Container Registry-based Image Cache Strategy

📅 2024-10-15 noisonnoiton

Overview

Section titled “Overview”

When building Docker images in GitHub Actions, rebuilding every layer from scratch each time lengthens CI runtime. One way to reduce this is container registry image-based cache management: store built image layers as a cache in a container registry, and reuse them in subsequent builds.

Key Concepts

Section titled “Key Concepts”
  • Registry cache stores the cache in a Docker registry.
  • Cached layers are stored in a centralized location and can be reused across multiple builds (different runners, different branches).
  • Unlike a local cache (the GitHub Actions cache action), a registry cache acts as a central store shared across the whole team.

Example: Registry-based Docker Image Cache Management

Section titled “Example: Registry-based Docker Image Cache Management”
  • context: Specifies the Docker build context. Here . refers to the current directory.
  • file: Specifies the path to the Dockerfile to use.
  • push: Specifies whether to push the built image to the registry. Set to true.
  • cache-from: Uses a previously stored cache from the container registry.
    • type=registry: Fetches the cache from a Docker registry.
    • ref: Specifies the registry reference where the cache is stored. Used with type=registry.
  • cache-to: Stores a new cache in the container registry.
    • type=registry: Stores the cache in a Docker registry, keeping it in a centralized location reusable across multiple builds.
    • ref: Specifies the registry reference where the cache is stored. Used with type=registry.
    • mode=max: Configures the cache to store as much cache data as possible.
  • tags: Adds the IMAGE_TAG and latest tags to the Docker image.

Considerations

Section titled “Considerations”
  • mode=max caches even intermediate build-stage layers, which increases cache storage size and cost. You need to understand and tune the trade-off between cache hit rate and storage cost.
  • It’s common to use a dedicated cache image repository (a *-cache repository) for the registry cache, kept separate from the actual deployment image repository so a different retention policy can apply.
  • The ${{ vars.ACR_LOGIN_SERVER }} and ${{ vars.ACR_REPOSITORY }} shown here are the standard pattern of referencing GitHub Actions organization/repository variables directly, with no actual registry address or repository name hard-coded.

Summary

Section titled “Summary”

A container registry-based cache provides a centralized cache store shared across a team, unlike GitHub Actions’ local cache. It can be adopted with just the cache-from/cache-to type=registry options and offers significant build-time reduction, but storage cost and retention policy need to be designed alongside it.
