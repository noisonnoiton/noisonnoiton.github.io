K8S(kubernetes) Object

Section titled “K8S(kubernetes) Object”

Each object can be created/modified by writing it in YAML format.

Each object is divided into namespace-scoped resources and cluster-scoped resources.

That is, the name of a namespace object must be unique within the namespace, and a cluster object must be unique within the cluster.

Deployment(pod)

Section titled “Deployment(pod)”

Defines the life cycle of a pod and the pod’s instances.

Service

Section titled “Service”

Declaration that exposes a container so that it can communicate with the pod. Pod IPs change dynamically, so they must be connected through a service. Connections take the form client -> service -> pod, and pod -> service -> pod

Ingress

Section titled “Ingress”

Acts as a web server for HTTP(S) communication and provides software-based L7 switch functionality, connecting backend services based on Host (Domain) information and the pattern of the sub-URL. It provides TLS Offload functionality, and SSL certificates can be registered as secrets and easily applied on the ingress resource.

configmap

Section titled “configmap”

A Configmap is an Object used to store non-confidential data in key-value pairs. A Pod can consume a Configmap as environment variables, command-line arguments, or configuration files in a volume. Using a Configmap, you can separate environment-specific configuration from the container image, making your application easily portable.

Caution

A Configmap does not provide security or encryption. If the data you want to store is confidential, use a Secret instead of a Configmap, or use additional (third-party) tools to keep the data private. A Secret is also simply Base64-encoded.

Usage

Section titled “Usage”

Configmap usage example : as environment variables, or mounted as files in a directory (existing paths are replaced) To mount only a specific file into an existing path, specify the file name with subpath.

Generally, when a configmap changes it is reflected inside the pod, but when using subpath a pod restart is required

Components

Section titled “Components”
  • storage class : provides functionality to connect Block/File systems. Supports the storage Life cycle through CSI (Container Storage Interface)
  • PV(Persistent Volume): a provided storage Instance that manages information such as accessmode (R/W/Once/Many), capacity, and reuse policy
  • PVC(Persistent Volume Claim) : maps the pod that uses the storage to the actual PV
