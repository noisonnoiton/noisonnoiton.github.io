Introduction

📅 2021-09-09 iamnogada

Spring Boot provides the same capabilities as the Spring Framework running in a Web Application, and
for Cloud Native environments it embeds the Web Application within the Spring Framework’s Application Context (Container),
making it a framework that can be managed as a single process.

tomcat model

Section titled “tomcat model”

By default, Tomcat runs as a single process, manages the resources (Datasource, Resource, http) needed by Web Applications within it, and the computing resources (CPU/Memory) allocated from the host are shared among the deployed WAR/EAR files. To control computing resources per application, you must run an independent Tomcat. When applying Microservices, it is difficult to tune computing resources by Workload and manage Instance Replicas this way.

Pros.

  • Consistent resource configuration makes integrated management by WAS Engineers easy
  • You can use JEE Specification features
  • Free to perform WAS tuning for the application (JVM, Datasource, TCP Pooling, etc.)
  • Application profiling is easy

Cons.

  • Requires Infra/Middleware Engineering knowledge (collaboration with other teams)
  • Additional work is needed for Build Once, Deploy Many
  • Fine-grained control of computing resources is difficult
  • JVM Corruption affects the entire Web App
  • Memory interference exists between Web Apps

Springboot Model

Section titled “Springboot Model”

Pros.

  • Best-practice defaults mean no general configuration is needed
  • The WAS is embedded, so it can run Standalone without a WAS (Deploy Many)
  • No Web/Was descriptor configuration needed: WAR, EAR
  • You can leverage the various boilerplate provided by the Spring foundation
  • Computing resources can be configured independently

Cons.

  • Inconvenient to use multiple Datasources
  • Inconvenient to use JSP (must be reconfigured for WAR deployment)
  • Supported WAS constraints : Tomcat, Jetty, Undertow
  • Constraints on leveraging JEE features (As-Is J2EE-based apps require Re-Architecture)
  • For multiple apps or MSA, a Gateway or LB is essential to control traffic
