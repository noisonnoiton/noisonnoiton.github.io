Multi Cluster Setup

📅 2021-09-17 jaemyeong.lee

Interactive Diagram

새 탭 ↗

  • Setup goals

    • Compose it of a Control Plane and Data Planes.
    • Automate the installation of the basic components installed on a cluster.
    • Automate the management of cluster endpoints.
    • Apply a Task Runner when controlling cluster resources from the DWP.
    • Apply async, non-block when controlling cluster resources from the DWP.
    • Apply status monitoring when controlling cluster resources from the DWP.
    • Handle Access Logs outside the application, or at least remove direct Redis access.

  • task list

    • App CI
    • App CD
    • App Pod execution
    • SRE Component

Deployment Diagram

Section titled “Deployment Diagram”

Site A

Section titled “Site A”
  • Only the components used by Site B are shown
  • Uses Harbor as the Docker registry
  • Uses TaskAgent, TaskRunner, and NotifyAgent for task-based asynchronous processing

Site B

Section titled “Site B”
  • Divided into Control Plane and Data Plane
  • Uses TaskRunner for communication with the Platform Plane
  • Uses Harbor as the Docker registry
  • Gitee is used as the user git repository
  • Bitbucket is used for the source used for deployment on the Platform
  • Uses ArgoCD for managing cluster components
  • The Monitoring/Alert components are divided into long-terms and short-terms

Cluster Management

Section titled “Cluster Management”
  • Describes the procedure for building a new cluster
  • The components to be installed on the Site Cluster are managed with ArgoCD
  • The ArgoCD Dashboard is used for managing deployment status

Create application process

Section titled “Create application process”
  • Considerations
    • Allow applications to be created regardless of site information.
    • Limit the scope to generating DWP metadata and providing the source repository to developers.
  • Items requiring review
    • Need technical verification of sending the status that occurs in the TaskRunner to the NotifyAgent
    • Need verification of the feature for querying the status that occurs in the TaskRunner

Create helm chart process

Section titled “Create helm chart process”
  • Considerations
    • Allow helm charts to be created regardless of site information.
  • Items requiring review
    • Need technical verification of sending the status that occurs in the TaskRunner to the NotifyAgent
    • Need verification of the feature for querying the status that occurs in the TaskRunner

App. CI process

Section titled “App. CI process”
  • Considerations
    • The TaskAgent needs a feature to discover the Target Cluster
    • Since the application source is not large in size, it is checked out at site A
    • The docker image size is large, which may cause network traffic problems
    • Due to network traffic problems, the docker repository must be located at site B
    • Due to network traffic problems, docker build & push must be performed at site B
    • Docker image synchronization between sites is required
  • Items requiring review
    • Need technical verification of sending the status that occurs in the TaskRunner to the NotifyAgent
    • Need verification of the feature for querying the status that occurs in the TaskRunner
    • Need verification of the docker image synchronization time and interval between sites

App. CD process

Section titled “App. CD process”
  • Considerations
    • Create the ArgoCD Application at the time deployment is performed.
    • The ArgoCD Application is also managed with bitbucket yaml.
    • ArgoCD metadata is kept on the control plane.

Helm CD process

Section titled “Helm CD process”
  • Considerations
    • When you create an ArgoCD Helm application, ArgoCD deploys the helm chart
    • The ArgoCD helm app. is also managed with a bitbucket repository
    • values.yml is modified via parameter settings within the helm app.
  • Items requiring review
    • Need a way to query the status of the async process
